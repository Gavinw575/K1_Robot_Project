Week 4 — SDK & Basic Motion Control

Learning Objectives

  • Know the three primary control modes: kPrepare, kWalk, kDamping
  • Send velocity commands using Move(vx, vy, vyaw)
  • Implement safe motion programs with proper initialization and cleanup
  • Write a program to walk forward 1 metre and turn 90 degrees

1. Booster SDK Architecture

The Booster Robotics SDK provides a Python (and C++) API that abstracts the low-level motor commands into high-level locomotion calls. The two most important classes are:

Class Role
ChannelFactory Manages the DDS network channel. You pass the network interface name (e.g., "eth0") and it handles discovery and transport setup.
B1LocoClient High-level locomotion client. Sends mode changes and velocity commands to the robot's motion controller.

2. Control Modes

Before any motion command can be sent, the robot must be in the correct mode. Modes are changed sequentially — you cannot jump from kDamping directly to kWalk.

Mode Description Typical Use
kDamping Joints resist motion passively. Robot can be physically moved. Safe idle state; always use for shutdown.
kPrepare Robot stiffens joints and moves to a neutral standing pose. Transition state before walking.
kWalk Active balance and locomotion controller enabled. Robot responds to Move() commands. All walking tasks.
⚠ Mode Transition Order
Always transition: kDamping → kPrepare → kWalk. Never skip kPrepare — the robot must reach its balanced stance before the walk controller takes over, otherwise it may fall.

3. The Move() Command

client.Move(vx, vy, vyaw) sends a velocity command to the locomotion controller. All values are in SI units:

Parameter Units Meaning Safe Range
vx m/s Forward (+) / backward (−) speed −0.5 to +0.5
vy m/s Left (+) / right (−) lateral speed −0.3 to +0.3
vyaw rad/s Counter-clockwise (+) / clockwise (−) rotation −0.5 to +0.5

4. Walk Forward 1 Metre and Turn 90 Degrees

import time
import booster_robotics_sdk as sdk

# ---------- configuration ----------
NETWORK_IFACE = "eth0"
FORWARD_SPEED = 0.3   # m/s
FORWARD_DIST  = 1.0   # metres
TURN_SPEED    = 0.4   # rad/s
TURN_ANGLE    = 1.5708 # 90 degrees in radians

def main():
    # Initialise channel and client
    sdk.ChannelFactory.Instance().Init(0, NETWORK_IFACE)
    client = sdk.B1LocoClient()
    client.Init()

    try:
        # 1. Prepare mode — robot stands up
        print("Entering kPrepare...")
        client.ChangeMode(sdk.RobotMode.kPrepare)
        time.sleep(3)

        # 2. Walk mode — balance controller active
        print("Entering kWalk...")
        client.ChangeMode(sdk.RobotMode.kWalk)
        time.sleep(1)

        # 3. Walk forward 1 metre
        duration_fwd = FORWARD_DIST / FORWARD_SPEED   # ≈ 3.33 s
        print(f"Walking forward {FORWARD_DIST} m...")
        t_start = time.time()
        while time.time() - t_start < duration_fwd:
            client.Move(FORWARD_SPEED, 0, 0)
            time.sleep(0.02)

        # Stop
        client.Move(0, 0, 0)
        time.sleep(1)

        # 4. Turn 90 degrees counter-clockwise
        duration_turn = TURN_ANGLE / TURN_SPEED       # ≈ 3.93 s
        print("Turning 90 degrees...")
        t_start = time.time()
        while time.time() - t_start < duration_turn:
            client.Move(0, 0, TURN_SPEED)
            time.sleep(0.02)

        client.Move(0, 0, 0)
        print("Done.")

    finally:
        # Always return to damping mode — this runs even if an exception occurs
        print("Returning to kDamping (safe state)...")
        client.ChangeMode(sdk.RobotMode.kDamping)

if __name__ == "__main__":
    main()
Why try/finally?
If your code crashes mid-motion (exception, Ctrl-C, network error), the finally block still runs and sends the robot back to kDamping. Without it, the robot continues executing the last Move() command indefinitely.

5. Safety: Always Initialize to kPrepare

  1. Power on the robot. Wait for green LED.
  2. SSH into the robot. Source the ROS 2 and SDK environment.
  3. Visually confirm the robot is in a safe stance (not leaning).
  4. Call ChangeMode(kPrepare) and wait 3 seconds for it to complete.
  5. Only then call ChangeMode(kWalk).
  6. Send all Move() commands with small values first to verify response.
  7. When done: Move(0,0,0) then ChangeMode(kDamping).
