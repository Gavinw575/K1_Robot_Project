Week 10 — Final Project

Learning Objectives
  • Integrate voice control, computer vision, and autonomous motion into one system
  • Produce clean, well-documented code in a public GitHub repository
  • Record a live demonstration video showing all required behaviors
  • Communicate your technical work in a written report and peer presentation

1. Integration Challenge

The final project combines everything you have built over the course:

  • Voice control (Week 6) — the robot must respond to spoken commands
  • Computer vision (Week 5 or 8) — the camera must influence at least one decision
  • Autonomous motion (Week 4, 7, or 8) — the robot must execute at least one fully autonomous behavior

You have flexibility in your implementation. Some example projects:

  • "Fetch the ball" — voice command triggers autonomous ball detection and retrieval
  • "Follow me" — YOLO person detection + proportional following + voice start/stop
  • "Security patrol" — pre-planned route + fall-back to damping on voice "stop" + person alert
  • "Tour guide" — voice-navigated waypoints + text-to-speech commentary at each stop

2. Demo Requirements

  1. At least 3 distinct voice commands must cause observable robot actions (not just a spoken reply). Examples: "walk forward", "find the ball", "stop and wait", "turn around".
  2. Camera-based decision — the robot must use the camera to make at least one real-time decision. This could be: detecting a specific object, avoiding an obstacle, tracking a person, or identifying a color.
  3. Autonomous behavior — after a trigger (voice or visual), the robot must execute a multi-step autonomous behavior without further human input. This runs for at least 10 seconds.
  4. Safe shutdown — at any point a "stop" voice command or Ctrl-C must gracefully stop all motion and return the robot to kDamping mode.

3. Architecture Sketch

# Suggested node architecture for the final project

/booster_video_stream ─────> [yolo_node]  ─────> /detections
/robot_interface/imu  ─────> [safety_node] ────> /fall_alert

[voice_node] ──(text)──> [command_parser] ──(action)──> [motion_node]
                                 ^
                         /detections, /fall_alert
                         (vision and safety can override commands)

[motion_node] ──────────────────────────────────> SDK / B1LocoClient

Keep each node focused on one responsibility. Use ROS 2 topics to pass data between them so each component is independently testable.

5. README Requirements

Your README.md must include:

  • Project title and description — what does your system do?
  • Demo video link — YouTube, Google Drive, or embedded GIF
  • System diagram — show how the nodes connect
  • Setup instructions — how to install dependencies and run
  • Known limitations — what does your system not handle well?
  • Future work — one or two improvements you would make with more time

6. Technical Report Outline

The technical report should be 1,500–2,500 words and cover:

  1. Introduction — what problem are you solving and why is it interesting?
  2. System Design — architecture diagram, node descriptions, data flow
  3. Implementation Details — key algorithms, parameter choices, and why
  4. Results — what worked, what didn't, measured performance (FPS, latency, success rate)
  5. Challenges & Solutions — at least 2 technical obstacles you overcame
  6. Conclusion — what you learned and what you would do differently
