Week 2 — ROS 2 Fundamentals

Learning Objectives
  • Understand the core ROS 2 concepts: nodes, topics, messages, and services
  • Configure FastDDS for Ethernet-based cross-machine communication
  • Use ros2 topic commands to inspect live robot data
  • Record and replay sensor data with rosbag2

1. What Is ROS 2?

ROS 2 (Robot Operating System 2) is a middleware framework for building robot software. Unlike ROS 1, ROS 2 is built on the DDS (Data Distribution Service) standard, giving it real-time capabilities, multi-robot support, and better security.

1.1 Core Concepts

Concept Description
Node A single executable process. Each node has a specific responsibility (e.g., camera driver, controller, planner).
Topic A named communication channel. Nodes publish data onto topics and subscribe to receive it. Topics are asynchronous and fire-and-forget.
Message A typed data structure sent over a topic. Examples: sensor_msgs/Image, geometry_msgs/Twist.
Service A request/response communication pattern. The client sends a request and blocks until the server replies. Used for discrete actions.
Action Like a service but with feedback streaming during long-running tasks (e.g., navigate to a goal).

2. FastDDS Configuration for Ethernet

By default, ROS 2 uses UDP multicast for peer discovery. On direct Ethernet links (without a multicast-capable switch) this fails silently. FastDDS with a static peer list solves this.

2.1 Create the FastDDS Configuration File

On your laptop, create ~/fastdds_k1.xml:

<?xml version="1.0" encoding="UTF-8" ?>
<profiles xmlns="http://www.eprosima.com/XMLSchemas/fastRTPS_Profiles">
  <transport_descriptors>
    <transport_descriptor>
      <transport_id>udp_transport</transport_id>
      <type>UDPv4</type>
    </transport_descriptor>
  </transport_descriptors>
  <participant profile_name="k1_participant" is_default_profile="true">
    <rtps>
      <userTransports>
        <transport_id>udp_transport</transport_id>
      </userTransports>
      <useBuiltinTransports>false</useBuiltinTransports>
      <builtin>
        <discovery_config>
          <initialPeersList>
            <locator><udpv4><address>192.168.10.102</address></udpv4></locator>
          </initialPeersList>
        </discovery_config>
      </builtin>
    </rtps>
  </participant>
</profiles>

2.2 Set Environment Variables

Add the following lines to your laptop's ~/.bashrc (and source ~/.bashrc afterward): 

# ROS 2 environment — add to ~/.bashrc on your laptop
source /opt/ros/humble/setup.bash

# Use the same domain as the robot
export ROS_DOMAIN_ID=0

# Force FastDDS as the RMW implementation
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp

# Point FastDDS to the static peer config
export FASTRTPS_DEFAULT_PROFILES_FILE=~/fastdds_k1.xml

2.3 DDS vs WiFi Discovery — Why the XML File Is Needed

ROS 2 DDS discovery works by broadcasting "participant announcement" UDP packets. On a WiFi network these broadcasts reach all devices automatically. On a direct Ethernet cable or an unmanaged switch the multicast packets may not be forwarded, so the two machines never find each other. The XML file hard-codes the robot's IP as an initial peer, bypassing multicast discovery entirely.

3. Topic Commands

# List all active topics
ros2 topic list

# Echo live messages on a topic (Ctrl-C to stop)
ros2 topic echo /low_state

# Show message type and connection info
ros2 topic info /booster_video_stream

# Measure publish rate (Hz)
ros2 topic hz /robot_interface/imu

# Show full message schema
ros2 interface show sensor_msgs/msg/Imu

4. Recording and Playing Back Rosbags

Rosbag2 lets you capture all topic data to disk and replay it later — invaluable for offline algorithm development. 

# Record all topics for 10 seconds into a bag named k1_test
ros2 bag record -o k1_test --duration 10 -a

# List what was recorded
ros2 bag info k1_test

# Replay the bag at normal speed
ros2 bag play k1_test

# Replay at half speed
ros2 bag play k1_test --rate 0.5

# Record only the camera and IMU topics
ros2 bag record -o k1_sensors \
    /booster_video_stream \
    /robot_interface/imu
