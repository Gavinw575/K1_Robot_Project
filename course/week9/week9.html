1. Reinforcement Learning Concepts

1.1 The RL Loop

In reinforcement learning an agent interacts with an environment through a cycle of observations and actions: 

At each time step t:
  1. Environment sends observation o_t to the agent
     (e.g., joint angles, IMU, foot contact states)
  2. Agent selects action a_t using its policy π(a|o)
     (e.g., joint torques or target joint angles)
  3. Environment transitions to state s_{t+1}
     (physics simulation advances by one timestep)
  4. Environment returns reward r_t
     (e.g., +1 for forward progress, -1 for falling)
  5. Repeat until episode ends (fall, timeout, goal reached)

Goal: learn policy π that maximises expected cumulative reward R = Σ r_t
Term Meaning K1 Example
Agent The learner / decision maker The neural network controlling the K1
Environment The world the agent acts in Isaac Lab / MuJoCo simulator
Observation What the agent sees Joint positions, velocities, IMU, commands
Action What the agent does Target joint positions (22 DOF)
Reward Scalar feedback signal Forward velocity − energy penalty − fall penalty
Policy The agent's decision function A 3-layer MLP neural network
Episode One trial from start to termination Robot walks until it falls or 20 seconds pass

2. Sim-to-Real Gap and Domain Randomization

A policy trained purely in simulation often fails on the real robot because of the sim-to-real gap: differences between the simulated and physical world.

  • Contact dynamics — simulators approximate friction and deformation; real rubber feet behave differently
  • Actuator dynamics — real motors have backlash, hysteresis, and latency not modeled in sim
  • Sensor noise — real IMUs drift; sim IMUs are perfect
  • Model errors — URDF mass/inertia values are approximate

Domain randomization counters this by adding random variation during training: random floor friction, random joint stiffness, random mass, random sensor noise. The policy learns to be robust to all these variations, so the real robot falls within the learned distribution.

3.1 Reward Function Structure

# rewards.py excerpt — typical locomotion reward components
def compute_reward(env) -> dict[str, float]:
    return {
        # Encourage forward velocity matching a command
        "lin_vel_x":     2.0 * exp(-4 * (env.base_vel_x - env.cmd_vel_x)**2),

        # Penalize lateral drift
        "lin_vel_y":    -0.5 * env.base_vel_y**2,

        # Penalize excessive joint torques (energy efficiency)
        "torque":       -0.0002 * (env.torques**2).sum(),

        # Penalize base acceleration (smooth motion)
        "base_accel":   -0.001 * (env.base_accel**2).sum(),

        # Terminate episode if robot falls
        "fall":         -10.0 * env.is_fallen,

        # Keep upright orientation
        "orientation":   0.5 * (env.projected_gravity_z - 1.0)**2 * -1,
    }

4. Running a Pre-Trained Policy in MuJoCo

The booster_deploy package includes a pre-trained ONNX walking policy that can be tested in MuJoCo before deploying to the real robot: 

# Clone the deploy repository
git clone https://github.com/BoosterRobotics/booster_deploy.git
cd booster_deploy

# Create conda environment
conda create -n booster_deploy python=3.10
conda activate booster_deploy
pip install -r requirements.txt

# Run the k1_mj2 task in MuJoCo simulator
python3 deploy/run_policy.py \
    --task k1_mj2 \
    --policy models/k1_walking_policy.onnx

# Controls (while MuJoCo window is focused):
#   W/S = forward / backward
#   A/D = turn left / right
#   Space = stop
